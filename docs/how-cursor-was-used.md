# How Cursor was used

Weather-or-Not is developed in a Cursor workspace with project rules in `.cursor/rules`. Cursor Agent wrote the deterministic tools that do the arithmetic the agent is not allowed to do itself: the degree-day SQL template and its reference implementation, the attribution (peer set, slope, seeded bootstrap, three-way split, confidence labels, claim verdict) and the like-for-like revenue layer (companyconcept history, recast detection, rule R1, frames helpers), each with its vitest suite. This page lists every Cursor task, its commits, and what was corrected afterwards.

## How the workspace is set up

- **`.cursor/rules/`**: the project rules (languages and style, test and commit conventions, safety rules such as "the model never computes numbers", Lightning SQL rules, the read-only vendored engines, data licences). The rule files were carried over from the sister project ClearShelf (same author) and still name it in places; the language, style, test and commit rules are what applied to these tasks.
- **Task files** in [`docs/cursor-tasks/`](cursor-tasks/README.md). Each one is a self-contained brief with the same sections: goal, workspace, files to read, inputs, deliverables, constraints, checks, out of scope, commit message. The inputs include the exact formulas of the method and a known-answer fixture in `agent/test/fixtures/` whose expected numbers were computed independently of the code under test (`make_fixtures.py`), so a task is green only when the implementation reproduces the method's numbers. Cursor Agent ran headless from the repository root:

  ```powershell
  & "$env:LOCALAPPDATA\cursor-agent\cursor-agent.cmd" -p --trust --force --workspace . --output-format text "Read docs/cursor-tasks/<file>.md and complete it. Run the listed checks until green."
  ```

- **Checks** are scoped to each task's files (`npx vitest run <filter>` and `npx tsc --noEmit -p tsconfig.tools.json`), because the repository was scaffolded from the sister project and still carried suites whose modules were not copied over.
- **Review.** Each run's changes were reviewed with `git diff` against the method in the build spec (formulas, the tenths-of-a-degree-C to F conversion, bootstrap percentiles, confidence rules, claim thresholds, rule R1) and committed unchanged as `Cn: <task> (Cursor Agent)`. Corrections went into separate commits (`Cn review: <what>`), so the history shows what Cursor Agent wrote and what changed later.

CLI version 2026.10.22, model `Auto`, Cursor Pro plan. All runs took place on 24 Oct 2026 (SGT).
